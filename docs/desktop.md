# Desktop inspector

AgentTrace includes a Tauri v2 + React desktop inspector under `apps/desktop`.

The desktop app is a local visualization layer over the same SQLite trace format used by the CLI. It does not require a hosted backend or a localhost API process.

## Features

- run browser with status, harness, timestamp, and local bookmarks;
- native file-picker import routed through the same harness adapters used by `agenttrace import`;
- live event/stat/artifact refresh while the selected run is active;
- event timeline with category filters and text search, including schema-v2 `browser.*` events when an adapter actually emits verified browser evidence;
- observed-only charts for token usage, explicit API latency, normalized event distribution, and longest event durations;
- complete capability evidence strip from the product adapter registry, including explicit unavailable categories;
- explicit native / inferred / derived / unavailable provenance badges;
- payload, raw-source, execution, terminal, diff, and relations inspectors;
- terminal evidence only for shell/process events or events with structured command metadata;
- unified and side-by-side diff rendering only when the trace actually exposes recognizable patch/diff text;
- span tree only from real `span_id` / `parent_span_id` relationships;
- subagent and context-provenance views only from explicit normalized lifecycle events;
- command, filesystem-impact, token, cost, duration, retry, and error views when the trace contains those fields;
- deterministic run comparison for event/token/retry/error measurements without an LLM-generated winner;
- sanitized JSONL export generated by the Rust backend;
- artifact metadata view with run/event linkage, size, type, compression state, and SHA-256 identity;
- raw-source visibility toggle for local debugging;
- persistent **System / Dark / Light** themes;
- compact DevTools-style layout intended for high-density debugging rather than decorative dashboards.

When evidence is absent, the relevant panel says `unavailable`; the frontend does not infer a patch, span, browser action, subagent, context change, terminal log, token count, duration, latency, or capability merely to fill the screen.

## Importing traces

Choose the harness first, then use **Import trace** in the sidebar. AgentTrace opens a native file picker scoped to common JSON/JSONL/NDJSON/log session files and sends the selected path to the Rust Tauri layer.

The selected file is normalized by the registered harness adapter, re-redacted with the active desktop policy, and appended to the same `TraceStore` used for recorded runs. The desktop does not maintain a separate JavaScript parser or import schema.

Import support remains harness-specific. If an adapter does not implement session/log import, the UI surfaces that adapter error instead of pretending the file was understood.

## Charts

Charts only visualize fields already present in the trace:

- **Token usage** — input, output, cached-input, and reasoning tokens that were actually reported/normalized;
- **API latency** — events with a typed `latency_ns` value derived from a semantically explicit upstream latency signal; Claude Code `duration_api_ms` is the first implemented example;
- **Event distribution** — counts of normalized event kinds;
- **Longest observed durations** — events with a real `duration_ns` value.

A chart says `unavailable` when the trace does not expose the required measurements. AgentTrace does not synthesize latency or token values from timing guesses or model-price assumptions.

## Themes

The toolbar supports **System**, **Dark**, and **Light**. The preference is stored locally in the webview. System mode follows the operating-system color-scheme setting and updates when that setting changes.

## Development

Install frontend dependencies and start Tauri from `apps/desktop`:

```bash
npm install
npm run tauri dev
```

The desktop uses the official Tauri dialog plugin for user-initiated trace selection. Its capability file grants the main window only core defaults plus the dialog permission needed for that workflow.

The Tauri crate is deliberately isolated from the root Rust workspace because the desktop runtime may require a newer Rust compiler than the AgentTrace core MSRV.

## Database selection

The desktop shell uses `AGENTTRACE_DB` when that environment variable is set. Otherwise it creates or opens `agenttrace.db` in the platform-specific AgentTrace application-data directory.

To inspect the same database as a CLI session, point `AGENTTRACE_DB` at the CLI database before launching the desktop app.

## Redaction profile

Set `AGENTTRACE_REDACTION_CONFIG` to the same additive JSON profile used by the CLI when organization-specific patterns are required:

```bash
AGENTTRACE_DB=/path/to/agenttrace.db \
AGENTTRACE_REDACTION_CONFIG=/path/to/agenttrace-redaction.json \
  npm run tauri dev
```

The Rust Tauri layer re-applies that policy before returning events or sanitized exports to React and before persisting desktop-imported events. Built-in safe rules remain enabled even when a custom profile is present.

## Trust model

The desktop app displays stored evidence. It does not reinterpret unavailable fields as observed telemetry. Raw-source views show only what was retained after persistence and the current desktop redaction pass.

Artifact bytes are not automatically loaded into the React UI; the current relations panel exposes metadata only. This avoids turning the inspector into an implicit arbitrary-file exfiltration surface.
